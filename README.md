# 대동제·해커톤 운영 로그 정규표현식 추출기

2026 전주대학교 대동제와 밤샘 해커톤 운영 로그(`data/festival_log.txt`)에서 필요한 값만 골라내는 파이썬 프로그램입니다. 로그에는 팀 등록 정보와 부스 정산 메모가 섞여 있고, 일부러 넣어 둔 잘못된 값도 있습니다. 도메인이 깨진 이메일, 자릿수가 모자란 전화번호, 작년 쿠폰 같은 것들입니다. 이런 값은 버리고 조건에 맞는 것만 남기는 게 과제의 핵심이었습니다.

외부 라이브러리는 쓰지 않았습니다. 표준 라이브러리 `re`만 있으면 돌아갑니다.

## 실행

파이썬 3.12에서 확인했습니다.

```bash
python extract.py
```

다른 로그 파일을 넣고 싶으면 경로를 인자로 주면 됩니다.

```bash
python extract.py 다른로그.txt
```

## 파일 구성

```
extract.py              추출 프로그램
data/festival_log.txt   과제에서 받은 원본 로그
```

## 문제별 정규표현식

### 1. 이메일

```python
r"[A-Za-z0-9._%+-]+@[A-Za-z0-9-]+(?:\.[A-Za-z0-9-]+)*\.[A-Za-z]{2,}"
```

`@` 바로 뒤에 영문자나 숫자가 한 글자 이상 오도록 했습니다. `hyunwoo@.ac.kr`은 `@` 다음이 곧바로 점이라 여기서 탈락합니다. 도메인 중간 부분은 `jj.ac.kr`처럼 점이 여러 번 나올 수 있어서 `(?:\.[A-Za-z0-9-]+)*`로 반복을 허용했고, 맨 끝은 두 글자 이상의 영문자로 끝나야 합니다.

### 2. 휴대폰 번호

```python
r"(?<!\d)010[-. ]\d{4}[-. ]\d{4}(?!\d)"
```

구분자는 문자 클래스 `[-. ]` 하나로 처리했습니다. 하이픈, 점, 공백 중 무엇이 와도 됩니다. `010-123-4567`은 가운데가 세 자리라 `\d{4}`에 맞지 않고, `063-3290-1114`는 010으로 시작하지 않아서 빠집니다.

앞뒤의 `(?<!\d)`와 `(?!\d)`는 더 긴 숫자열의 일부가 잘려서 잡히는 걸 막으려고 붙였습니다. 이 로그에는 그런 경우가 없지만, 없으면 `9010-1234-56789` 같은 값에서 가운데만 뽑혀 나옵니다.

### 3. 학번과 학과

```python
r"\[(202\d{6})\s*/\s*([^\]]+?)\s*\]"
```

그룹을 두 개 두었기 때문에 `findall`이 `(학번, 학과)` 튜플 리스트를 그대로 돌려줍니다. 학번은 `202` 뒤에 숫자 여섯 개, 합쳐서 아홉 자리입니다. 외부인 `999900000`은 앞자리가 다르고, `20261122`는 여덟 자리라 둘 다 걸리지 않습니다.

학과명은 닫는 대괄호가 나오기 전까지를 `[^\]]+?`로 받았습니다. 게으른 수량자를 쓴 건 학과명 뒤에 공백이 있을 때 그 공백까지 딸려 오지 않게 하려는 것입니다.

### 4. GitHub 저장소와 쿠폰

```python
r"https?://github\.com/[\w.-]+/[\w.-]+"
r"\bFEST-2026-[A-Z0-9]{4}\b"
```

호스트를 `github\.com`으로 못 박았으니 `gitlab.com` 주소는 따로 제외 처리를 하지 않아도 맞지 않습니다. 로그에 `http://`로 적힌 주소가 하나 있어서 `s?`로 둘 다 받았습니다. 그 주소는 끝에 `.git`이 붙어 있는데, 원문 표기를 살려 그대로 출력합니다.

쿠폰은 연도를 `2026`으로 고정했습니다. `FEST-2025-OLD9`는 연도에서 걸러집니다.

### 5. 부스 매출 합계

```python
r"매출:\s*([\d,]+)원"
```

금액처럼 생긴 숫자는 로그에 많습니다. 카드 1,100,000원, 현금 250,000원, 쿠폰 5,000원권이 다 그렇습니다. 하지만 각 부스의 총매출만 `매출:` 바로 뒤에 옵니다. 그래서 금액 패턴을 정교하게 짜는 대신 앞에 붙은 `매출:`을 기준으로 삼았습니다. 뽑은 문자열에서 쉼표를 지우고 `int`로 바꿔 더합니다.

## 해 보고 알게 된 것

이메일 문제에서 처음에는 `\S+@\S+` 정도로 시작했는데, 이러면 깨진 주소까지 전부 잡힙니다. 잘못된 값을 나중에 걸러내는 것보다 패턴에서 `@` 뒤 첫 글자를 제한하는 편이 훨씬 간단했습니다.

매출 문제도 비슷했습니다. 숫자 모양만 보고 구분하려면 조건이 계속 늘어나는데, 숫자 앞의 글자를 기준으로 잡으니 한 줄로 끝났습니다. 정규표현식을 짤 때는 찾는 값 자체보다 그 주변에 무엇이 있는지를 먼저 보는 게 빠르다는 걸 배웠습니다.
